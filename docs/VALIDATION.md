第一轮测试复现了六个失败用例：右键误开卡片、往返拖动误判、取消触点误判、说明弹窗保留移动键、漫游重进残留触点，以及空数组被错误接收为对象。修正后这六项与其余检查全部通过。另修正了画质降级只改变 Renderer 而未同步 Composer 的 DPR 问题，以及读取界面状态时的数据滞后。

这些结果证实了输入处理和数学状态变化，不能替代真实浏览器的 GPU、布局、事件分发与设备手感检查。

## 尚未验证

当前检查浏览器返回 `GL_VENDOR = Disabled / GL_RENDERER = Disabled`，无法创建 WebGL 上下文。用默认功耗策略重试后仍失败。因此以下项目虽已实现，但不能声明已通过浏览器验收：

- 浏览器中的 Three.js 完整渲染、天空 Shader、阴影、SSAO 与最终材质效果。
- 鼠标旋转、右键平移、缩放和触屏手势。
- 自动环绕暂停与恢复在真实浏览器中的实际手感（DOM 逻辑检查已通过）。
- 页面按钮触发的爆炸、重组、结构模式及自动演示的浏览器视觉全过程（状态与变换检查已通过）。
- Hover、构件点击、知识卡片、全屏和步行漫游的真实设备表现（部分事件及状态逻辑已通过）。
- 实际窗口 Resize、手机竖屏 / 横屏、浏览器字体排版和 200% 字号下的显示。
- WebMCP 在实际支持该能力的浏览器中的注册与执行（模拟接口的参数与状态检查已通过）。
- 实际设备帧率、GPU 占用、Safari / iOS 兼容性、跨浏览器透明排序。
- 真实测绘精度、所有隐藏节点的穿插关系及全寺院地形还原。

离屏检查图不是网页截图，使用了另一个基于实际模型数据的着色器。它能帮助核对比例、曲面、层次和明显悬空，不能代替 Three.js 的 WebGL 视觉验收，也不能证明每一个隐藏节点均无穿模。

## 在支持 WebGL 2 的浏览器中继续验收

1. 执行 `npm ci`、`npm run typecheck`、`npm run verify`、`npm run build`。
2. 执行 `npm run dev`，打开本地页面，检查 Console。
3. 旋转、平移与缩放；确认镜头不会进入地下。
4. 打开自动环绕，手动拖动后观察暂停及 4 秒后恢复。
5. 拆解、重组，并在动画中途反向；可查看 `#app` 的 `data-restored` 状态。
6. 检查结构模式、各类构件卡片、37 秒演示、院落步行及全屏。
7. 调整窗口尺寸并在真实触屏设备上检查；观察 FPS 后按需要调整 DPR 和场景密度。

本项目以诚实记录验证范围为原则，不把编译通过或离屏图当成浏览器交互全部通过。
